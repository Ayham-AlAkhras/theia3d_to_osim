# Theia3D in OpenSim
Convert Theia3D markerless motion capture data to skeletal joint angles and pelvis displacements (coordinates) for the [Rajagopal2016 model](https://simtk.org/projects/full_body) in OpenSim.

<img width="3210" height="1616" alt="upper_body" src="https://github.com/user-attachments/assets/9137c746-0ce0-4b70-8c53-20e5669c3794" />

These scripts were built using OpenSim 4.5 and Python 3.11, and tested with data from Theia3D 2022.2.

Before running the code, open the Anaconda prompt and set up the environment using the spec file located in this repo's _SpecFiles_ folder:

```
conda create --name theia2osim_latest --file spec-file-opensim45-python311.txt
```

Then switch your IDE's environment to "theia2osim_latest" and run scripts 1–5 in sequence, adjusting parameters in each script as needed.

Please cite the following paper in work that uses these scripts: AlAkhras A, Baklouti F, Bailey CA, Graham RB, Uchida TK (2026). Calibration and verification of OpenSim models from Theia3D markerless motion capture.

## Usage Notes
The data used for script1 is not the native output from Theia3D. If you have .c3d files from Theia3D, convert them to .txt files using Visual3D (note that OpenSim 4.5 cannot process the .c3d files from Theia3D). Each .txt file will contain 4×4 transforms in row-major form for each body segment (columns) and time step (rows).

These scripts can be used even if only Theia3D data are available by applying the default "offsets" we have computed for each coordinate; however, script5 is currently set up to compute these offsets using marker-based mocap data. Although the script can address desynchronization if given the correct parameters, it's best if the Theia3D data are spatially and temporally synchronized with the marker data.

## script1_parseTheiaData
This script processes a .txt file from Theia3D containing transformation matrices and generates a .pkl file that contains movement data. This file can then be written to a .trc file containing joint center locations (origins) using script2. The parser performs the following tests to ensure that the .txt file is in the correct format and that the data make sense:

  1. The first row must contain a number of entries that is a multiple of 16.
  2. The first four rows must have the same number of entries.
  3. There must be 16 unique, consecutive transformation matrix indices for each body segment.
  4. Each line of data must be of the same length.
  5. The value of each entry must be a floating-point number.
  6. There cannot be any perspective projections.
  7. All rotation matrices must be orthogonal.
      - The matrix multiplied by its transpose must result in an identity matrix.
      - The determinant of a matrix must equal 1.
      - The inverse of a matrix must be equal to its transpose.
  8. The world-frame rotation matrix must be an identity matrix throughout the motion.

## script2_createTRCFile
This script generates a .trc file containing position information on joint origins from Theia3D for use in OpenSim. The input to this script must first be generated using script1_parseTheiaData. If you want to use only orientation data from Theia3D in this workflow, set the flag `justRootBodies` to `True`.

## script3_generateTLOModel
This script generates an OpenSim musculoskeletal model that is designed to imitate Theia3D's proprietary model; we call this model the "Theia-like OpenSim" (TLO) model. The TLO model is an intermediary model that allows us to visualize and verify the data according to [Theia3D's "Default Model"](https://docs.theiamarkerless.com/apollo-v2024/theia3d-documentation/theia-model-description). Note that this script generates the TLO model according to the Theia3D data at a specified time step; the state of the model at this time step is the TLO model's default pose. The inputs to this script must first be generated using script1_parseTheiaData.

## script4_runFusedInverseKinematics
The Theia3D data give us 4×4 transforms containing the frame origin location and orientation for each body segment at each time step. Specifically, each "origin" is the location of a joint center from Theia3D, which is equivalent to the location of a joint's child-body frame in the TLO model. Each origin has a corresponding marker attached to the body segment with relative position of (0,0,0). Each "orientation" describes the orientation of a body-segment frame. This script runs inverse kinematics (IK) on the Theia3D data, using just the origins or using both the origins and the orientations.

## script5_mapTLOCoordinatesToRajagopal
This script maps coordinates for the TLO model (generated by script4_runFusedInverseKinematics) to coordinates for a separately scaled Rajagopal2016 model. The Theia3D and Rajagopal2016 human kinematic models represent human movement differently. This script uses temporally synchronized marker and markerless data to calculate the average difference between the two models. It then uses that average difference to apply "offsets" to the markerless data, converting them into joint angles in the OpenSim model that represent the same human motion. If you wish to use this workflow in the absence of marker data, you can do so using the default offsets we have provided. These offsets were averaged from 40 participants (22 females), each walking continuously at steady state for 12 gait cycles starting at heel strike.

## Miscellaneous Information
### Detecting Heel Strike
We used the method described by [Zeni Jr., et al.](https://doi.org/10.1016/j.gaitpost.2007.07.007) to detect heel strikes during walking.

### Joint Names
Some coordinates in our model differ from those used in the default Rajagopal2016 model. If you would like to use these scripts with the default Rajagopal2016 model, the coordinates can be renamed in the model file or changed in the scripts.
